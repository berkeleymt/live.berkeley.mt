# Status tracking

- [STATUS](STATUS.md) is the current evidence-based summary, not a backlog dump.
- [Decisions and inputs](decisions.md) contains unresolved questions, proposed defaults and owners still needed.
- [Development plan](../development-plan.md) contains vertical slices and acceptance criteria.
- [ADRs](../adr/0001-product-direction.md) record major decisions; accepted vs proposed must be explicit.
- `log/` records work completed, checks actually run and anything not verified. Use [the template](log/_TEMPLATE.md).

Before a change: identify requirements and preservation risks. After a change: update status, add a short dated log, and link evidence. Tick a requirement only when its acceptance criteria are actually met. Historical test results are not a new verification. Record user approval with its source; do not self-approve an unanswered question. Do not copy personal data into evidence screenshots or logs.
