## Changes

- Added `server/src/remote_content.rs`: dedicated bare Git object store, allowlisted complete `content/` schema v1 (manifest/operations/event/site/wayfinding/media), bounds, regular-file/hash/signature/reference validation, immutable snapshot activation. No app worktree checkout/code execution; current root tree entries are retained in editor commits. Public routes read the in-memory bundle, not Git.
- Added `LIVE_CONTENT_REMOTE_REPO` with `LIVE_CONTENT_BRANCH` and fixture-only `LIVE_CONTENT_ALLOW_LOCAL_REMOTE=true`. Refuse simultaneous local/remote mode, non-bare checkout, shallow/index/lock/alternate-origin mistakes; require trusted operator-owned config and one process per durable repository. Bounded Git commands and background full-jitter polling/backoff. No automatic production import or rewrite.
- Staff edits, direct file changes, uploaded media and restore converge on the same validator/remote ref. Full-base SHA/content-digest CAS permits unrelated code-only remote commits but rejects competing content. Staff success requires normal push and exact remote confirmation, never just a local commit. Last-good persists in `refs/live/loaded`; rejected/unconfirmed local commits persist in `refs/live/pending`; explicit archive retains `refs/live/drafts/<sha>`. Forward restores can repair an invalid remote commit without resetting code/history. Scheduled-notice gates and delivery deduplication remain unchanged.
- Bound event/site/wayfinding stores and live operations to that shared pointer only in remote mode. SQLite, file stores and `LIVE_CONTENT_REPO` retain their existing publication semantics. Private accounts/sessions/roster/report/subscription data are not read by the public exporter. Existing `/classic`, routes, editors/media and private inbox flows remain.
- Added explicit sync/pending/archive and Super-only configuration guidance endpoints; reused existing push/restore/export/CRUD contracts. `/media` serves only current loaded hash-named assets in remote mode. Upload returns previous/current revisions; SiteEditor only advances an exact matching base, never silently rebases a changed document.
- Publishing panel shows loaded/last-observed remote/branch/check time/pending/invalid-last-good state; supports fetch/validate, retry, JSON download, archive and restore with intentional confirmations. Super configuration action is hidden from Admin and server-enforced. Legacy local Git mode still separates local publication from remote backup. Mutation timeouts allow 90 seconds without automatic retries; ambiguous responses require status reconciliation.
- Added 6 local bare-origin scenarios in `tests/remote-content.test.mjs`, 3 JSDOM publication cases in `tests/staff-web.test.mjs`, and 2 conservative build-filter cases in `tests/content-build.test.mjs`. Isolated file-mode site/wayfinding test hosts use uninhabited remote adapters (cannot be constructed or simulate remote success); production remote behavior is exercised against the actual main/router in the new suite. No existing tests were disabled.
- Added `scripts/content-build-needed.mjs` and workflow filter: only an explicit Actions variable `LIVE_CONTENT_RUNTIME_RELOAD=true` skips content-only push builds/deploys after migration. Code/schema/manual/unknown changes still build; skipped content runs do not cancel an active code build. No Actions run or deployment was triggered.
- Updated publication/migration guide, protocol, architecture, ADR, implementation plan, decisions and status. [Operating guide](../../git-publishing.md) covers exact schema, migration including exclusion of the existing example file, media hash renaming, branch-policy limitation, retained-draft recovery, durable/single-owner assumptions and rollback to compatibility modes.
