## Sync and failure contract

- Production origin is hard-coded `https://api.contestdojo.com`; only GET `/events/{event_id}/students/`, `/teams/`, `/orgs/` with bearer auth. No arbitrary host override or redirects. Each request has a 5-second connect and 20-second total timeout; the three reads are sequential (manual client timeout 70 seconds).
- Students are required. A failed token, unknown event, transport/timeout, non-array/non-object shape, invalid JSON, oversize body or invalid required row fails the import. Teams/orgs are optional: failures or oversized/invalid joined enrichment omit that enrichment and report safe notes while retaining students. Responses never echo provider bodies/tokens/URLs.
- Bounds: 8,000,000 bytes and 20,000 rows per response, dotted-column nesting depth 12, bounded 256-byte column names, 8,192-byte cells, 256 union columns, 16,000,000-byte flattened rows and 20,000,000-byte serialized private snapshot, 128,000-byte settings/mapping requests. Lists become text; duplicate flattened keys fail rather than silently overwrite. A missing name is synthesized from first/last when available. Imported raw fields are **all private**, not a public export.
- A single async lock serializes manual/background sync and settings/mapping/clear. Overlap returns 409, never partial results. Provider work occurs without holding the snapshot mutex. The complete bounded SQLite value commits before replacing memory. Any required-source or storage failure retains last-good rows/mappings; no empty-success substitution. Unchanged rows keep the mapping revision stable; successful-check metadata is persisted in the same bounded value.
- Successful sync records check/success times; diagnostics also expose last attempt, failure and next eligible attempt. Failure backoff waits 60 seconds plus jitter within an exponentially growing window capped at 900 seconds; the minute scheduler still checks eligibility. Manual Sync observes the same cooldown (30 seconds after success, 60 seconds after storage failure). Saving corrected settings resets the cooldown. Auto skips disabled, unconfigured, demo and busy stores.
- Event changes clear mappings and retain the old private snapshot only for staff diagnosis. Public availability requires snapshot event to equal configured event, so old assignments cannot masquerade as the new event. Clear requires the explicit `CLEAR` confirmation, drops rows/provenance and does not change ContestDojo or erase settings. Enabled auto-sync can repopulate cleared data: disable it before retirement. Removing the token disables new production lookups/sync but does not delete saved private rows; use Clear to remove the local snapshot.

## IDs, fields, participation and room matching

- Default ID column is `number`. An explicitly chosen column is authoritative; there is **no hidden fallback to another field** after a mapping is saved. This deliberately differs from Lemon's private display fallback. Missing IDs and all rows in a duplicate normalized-ID group are unlookupable; every source row remains available to authorized staff for diagnosis.
- Normalize by trimming/collapsing whitespace and uppercasing, preserving leading zeros. IDs are not authentication. Staff-only mapped view supports name, tests, school, org, team and contact, plus paginated raw rows (50 per request). Private display fields have no implicit fallback.
- Optional `fields.tests` participates in projection: exact public schedule IDs separated by commas/semicolons. A blank/unknown value suppresses assignments. Leave None when participation is already expressed through per-test room cells, or when provider labels have not been reconciled. No inference from merely appearing in the public schedule.
- `roomColumns` maps schedule IDs to source columns. Multiple tests can share a column; None/empty omits that test. Blank room values omit that assignment. Reject unknown columns, unknown schedule IDs, unknown field purposes, nonnormalized aliases or nonexistent public room targets. Save reinterprets existing rows without fetching or editing ContestDojo.
- Room normalization collapses whitespace, uppercases and strips trailing parenthesized sections. Exact public room IDs and an unambiguous `building name + room code` match automatically. Explicit normalized aliases take precedence. No fuzzy cross-building match and no inference that a room code alone identifies a building. Ambiguous/removed targets become unmatched.
- Successful public lookup returns only schedule ID/title, scheduled start/end, matched public room ID or `unmatched`, and bounded demo/staleness/check metadata. A nonempty unmatched source room yields a generic help-desk state, **never its private raw label**. Scheduled times link to the live schedule for delays; they are not computed timer or delayed-time values. Deleted schedule IDs are omitted; staff can remove obsolete mappings.

## Privacy and abuse boundaries

`POST /api/rooms/lookup` accepts only `{ "studentId": "…" }` in a 4 KiB body. Unknown, malformed and ambiguous IDs share a generic 404. Successful results omit names, teams, schools, contacts, input IDs, raw rows, arbitrary source fields and credentials. No anonymous search/list/autocomplete/download exists. Status has no roster counts, event ID or provider settings.

All lookup/status responses carry `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer`. Same-origin/Fetch Metadata checks reject cross-site lookup. The client sends no referrer, does not queue/retry, keeps input/results only in component memory, clears the ID on success and all private details on tab hiding/unmount. The private subtree is `translate="no"`; future translation must not serialize its values. Reverse proxy/APM/analytics must also exclude request bodies and private staff rows; configure that operationally.

Every attempt (including successes) consumes a ten-minute fixed window: 20 per SHA-256-normalized ID, 600 per actual peer and 6,000 globally, with a bounded roughly 8,192-bucket table. 429 has `Retry-After: 600`. Forwarded headers are ignored; missing peer shares `unknown`. These process-local bounds reset on restart. Behind a reverse proxy a shared campus audience may hit one bucket; separately approve trusted-proxy/edge controls and scale/privacy testing. Do not claim elimination of enumeration risk: knowledge of an ID intentionally permits its minimal assignments.
